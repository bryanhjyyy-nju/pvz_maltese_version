# 战场性能测量

本次基准对比提交 `28cb80e` 与共享动画帧版本，在同一台 Windows 电脑、Qt 5.15.2 Release 下串行运行。

拥挤场景包含 45 株小白、48 只三种金毛和 40 发音符，开启双方血量。冻结战斗决策，保留动画与移动，预热 0.4 秒后记录 3 秒。完整绘制耗时取五组、每组 120 次的中位数。

| 测量 | 原版本 | 本次版本 |
| --- | --- | --- |
| 1280×720 稳态进程内存 | 486.2 MiB | 85.7 MiB |
| 1920×1080 稳态进程内存 | 493.3 MiB | 97.9 MiB |
| 1280×720 完整绘制 120 次 | 231 ms | 221 ms |
| 1920×1080 完整绘制 120 次 | 403 ms | 349 ms |
| 1280×720 重绘间隔的第 95 百分位 | 19.1 ms | 16.8 ms |

1080p 的绘制耗时降低约 13%，稳态内存降低约 80%。这些数字说明相同工作量的资源消耗下降，实际显示帧率仍受电脑和显示器影响。基准中的每秒 paint 事件数量包含零散局部重绘，不能当作显示帧率；统一动画时钟会合并这些事件。

## 改动

- `spriteanimation.*` 一次解码并缩放 GIF，缓存整段动画；同类角色和开场预览共用像素，每个角色仍有独立播放进度。缓存预算 32 MiB，正在使用的动画保留引用。
- 播放时钟使用 Qt 的统一动画调度，帧没有变化时不发送刷新。暂停、死亡和退出与其他动画一起停止。
- 背景交给场景背景绘制和视图缓存，窗口尺寸改变时由 Qt 重建缓存。
- 动态战场关闭空间索引维护，碰撞继续按排查找。角色使用设备坐标缓存，动画帧、受击与死亡效果变化会正常使缓存失效。

回归逐帧对比所有小白、金毛的像素与原 GIF 解码结果，检查原始帧时长和循环；同时验证独立时钟、血量、受击、暂停以及开场预览。
